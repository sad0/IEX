# Engine fixes

Engine bugs that EEex fixes and IEX must fix too (rule: never less than EEex), on Windows and Linux, on by default.
Implementation: `src/core/engine_fixes.cpp`. Test: `tools/fixtest` (below).

Source: public bug descriptions in the EE Fixpack thread "[code] Code fixes, aka stuff we can't fix" on G3
(https://www.gibberlings3.net/forums/topic/34892-code-code-fixes-aka-stuff-we-cant-fix/), posts marked
"Fixed via EEex" / "Fixed (requires EEex)". Pages 10-11 read 2026-10-31; pages 1-9 scanned 2026-10-31 (135 posts):
no other bug said to be fixed by EEex. Page 1 has #13 (old EEex); page 3 has a pathfinding bump/group-move bug that
no post says EEex fixes; page 6 repeats #2.

Clean room: only the bug descriptions and expected behaviour come from the thread. No EEex code, hook list or
implementation detail is used. Each fix is found and written from our own engine analysis (Linux symbols, Windows
matching; the Windows functions are in `IEX-data/engine/win/verified_fixes.json` with their evidence).

## Switches

All fixes are on by default and installed when the engine's Lua state is ready (Baldur.lua is loaded by then, no
game code has run). Baldur.lua (IEX options, tab "Engine Fixes"; read when the game starts):

- `SetPrivateProfileString('IEX','Engine Fixes','0')`: every fix off.
- `SetPrivateProfileString('IEX','Engine Fix <name>','0')`: one fix off, e.g. `'Engine Fix xpFloor'` (names in the table).

Environment variables take precedence: `IEX_ENGINE_FIXES=0` / `1` decides all fixes whatever Baldur.lua says,
`IEX_ENGINE_FIXES_OFF=name,name` turns those fixes off (when it is set, the per-fix Baldur.lua keys are not read). Lua: `IEX_EngineFixes()` and `IEX_Features.engineFixes` give `{name = installed}`.
IEX.log: `Engine fixes: on: ...; not installed: ...`. A fix whose engine bytes differ from the expected ones (other
build, another patch) is left out and listed as not installed.

## How each fix works (BG2EE 2.7.3)

- **1 op182**: the `CGameSprite::FindItemPersonal` call of `CGameEffectApplyEffectEquipItem::ApplyEffect` is
  redirected; the wrapper returns 1 for any slot found (amulet slot 0 included) and 0 for -1 (not found).
- **2 + 12 weapon speed**: `CGameSprite::Swing` sets the speed factor as `max(0, ability speed - speed bonus stat)`,
  then adds the 1d6-3 roll. The `max` call (description constants `IEX.fix.swingMaxSite`, `IEX.fix.swingRegs`: the
  sprite, item and ability registers at the call) gets a register-context hook that replaces the ammo's speed by its
  launcher's (`GetLauncher` + `CItem::GetAbility(0)`, as Swing itself finds the launcher) and adds the WSPECIAL SPEED
  cell (column 2) of the proficiency level, the larger of weapon and launcher as `CheckCombatStatsWeapon` does for the
  HIT / DAMAGE columns. The vanilla table has SPEED -1 at High Mastery and -3 at Grand Mastery (lower = sooner).
- **3 SPLPROT**: `CRuleTables::Compare` (only reached from `IsProtectedFromSpell`) is replaced by the same 12
  relations with signed `<=`, `<`, `>`, `>=`.
- **4 TRAPLIMT**: in `CGameEffectSetSnare::ApplyEffect` the compare after `GetSetSnareLimit` refused only
  `traps set > limit`; one jump condition byte makes it `traps set >= limit` (Linux `jg` -> `jge`, Windows `jle` ->
  `jl`). A class with no TRAPLIMT row reads the table's default (0) and so can no longer set any trap.
- **5 op33**: the mode-3 current-pass write `sub word [sprite + 0x1136]` becomes `+0x1134` (one displacement byte).
- **6 immunity strings**: `CGameEffect::CheckAdd` replaced the string of a matched spell-immunity entry by -1 unless
  it was 0xF00074 / 0xF00080, just before the feedback. The store is removed (Linux: 7-byte nop; Windows: the
  `cmove`/store sequence rewritten to keep the string and still turn 0xF00074 into 0xF00073 without a resource).
- **8 HP tables**: the call of `RollHitPoints(C2DArray const&, ...)` from `RollHitPoints(uchar, uchar,
  CDerivedStats&, ...)` is redirected. The wrapper rolls one level at a time through the engine's own function (dice,
  maximum-HP option, minimum roll); a level with dice gets its MODIFIER (or the caller's override) before the
  per-class divisor, as a level without dice already did.
- **9 Simulacrum**: the `GetActiveInactiveClasses` call of `CGameEffectCopySelf::ApplyEffect` gets the creature's
  own class back as the active class, so `GetAverageLevel` averages LEVEL / LEVEL2 / LEVEL3 for dual- and multi-classes.
- **10 AddXPObject message**: its `CGameSprite::FeedBack(50, value)` call (constant `IEX.fix.xpFeedbackSite`) shows
  `CInfGame::FeedBack(2, value)` for a loss: "The Party Has Lost Experience: N", as AddExperienceParty.
- **11 XP floor**: the `CGameEffectXP` vtable ApplyEffect slot (constant `IEX.fix.slot.xpApply`) gets a wrapper: a
  permanent op104 that would take the XP below 0 (increment, or a negative set / percentage) gives 0.

The new constants and the Windows symbols were added to `engine/*.iexd` directly; `tools/engine/gen_all.sh` has
them too, but regenerating every description from IEX-data today also drops fields added by hand since (CCreature
script fields, `m_nCopyParent`, ConcentrationFailed call sites...): to be fixed before the next full regeneration.

## Not done

- **7 kit list**: the "Mage" entry is kit 0 of `CScreenCreateChar::UpdateKitPanel` (CLSRCREQ check only); its name
  comes from `CRuleTables::GetClassStringLower(class, 0x4000)`, which reads MGSRCREQ row 0 (generalist) for the race
  and, when it is not 1, takes the first usable school's kit instead. The fix (leave kit 0 out of the list in that case)
  changes chargen for races that rely on it (gnome illusionists in some setups) and needs a chargen test with such a
  race and modded MGSRCREQ / KITLIST before it can ship. Not implemented yet.

## 13 event triggers (beyond EEex)

The thread credits only old EEex (2022). Observed 2026-11-01 with `tools/trigtest` (behaviour only, EEex run as a
black box in its own test copy): current EEex (the testgame's EET 2.7.3 install) shows the bug exactly as the engine
does. IEX fixes it anyway (maintainer decision, 2026-11-01): `eventTriggerObjects`, on by default, `src/core/engine_fix_triggers.cpp`.

Cause: `CAICondition::TriggerHolds` (Windows; on Linux also two copies inlined in `CAICondition::Hold`) calls
`CAIObjectType::Decode` on the script's own trigger object before `CAITrigger::OfType` matches it against each pending
event. Decode writes the found creature's instance id into the object and drops its object functions, so the script
keeps that creature for good. Fix: each Decode / OfType pair (found by the Decode call sites of the description whose
next call is OfType: 1 on Windows, 3 on Linux) gets call-site hooks; an object with object functions is decoded on a
temporary copy (CString name copied with the engine's own `CString::operator=`) at the OfType call, so it is resolved
again on every evaluation, as status triggers and `NextTriggerObject` already do. Objects without object functions
keep the engine's in-place decode. The Decode sites already go to IEX's `EEex_LuaObject` / `EEex_Target` decode; the
fix chains to it.

`tools/trigtest/run.ps1 -Side eeex|iex` (Windows, EET save AR2100, A = the main character, B = Imoen) and
`tools/trigtest/run_linux.sh on|off` (WSL, BG2EE "Chapter 1 Start", B = Imoen): a test creature (`IXT13D`, the
game's CAT.CRE with script `IXT13`: `Heard(PartySlot1,99)` / `AttackedBy(PartySlot1,DEFAULT)`, then the same triggers
with `[ANYONE]` as control) is spawned next to the party; portrait 1 (A) and 2 (B) shout or attack it one at a time,
before and after `worldScreen:SwapPortraits(0, 1)`. Which block counted the event:

| Step | Correct | EEex | IEX fix off | IEX fix on (W) | IEX fix on (L) |
|------|---------|------|-------------|----------------|----------------|
| A shouts, A in portrait 1 | PartySlot1 | PartySlot1 | PartySlot1 | PartySlot1 | PartySlot1 |
| B shouts, B in portrait 2 | other | other | other | other | other |
| portraits swapped; B shouts, B in portrait 1 | PartySlot1 | other | other | PartySlot1 | PartySlot1 |
| A shouts, A in portrait 2 | other | PartySlot1 | PartySlot1 | other | other |
| B attacks, B in portrait 1 | PartySlot1 | other | other | PartySlot1 | (no event) |
| A attacks, A in portrait 2 | other | PartySlot1 | PartySlot1 | other | (no event) |

IEX fix off = `IEX_ENGINE_FIXES_OFF=eventTriggerObjects` (W + L, same as the engine). On Linux the attack orders gave
no AttackedBy event in that save; Heard goes through the same code. Results in `IEX-data/trigtest/`: `eeex-1101-0122`,
`iex-1101-0144` (off), `iex-1101-0150` (on), `linux-fixoff-1101-0146`, `linux-fixon-1101-0147`.
